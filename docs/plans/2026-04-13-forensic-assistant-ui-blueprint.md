# 法医助手三端页面原型说明书

## 1. 文档目的

本说明书用于指导 `learner`、`expert`、`client` 三类角色界面的信息架构、页面模块、关键交互与实施优先级设计。

目标不是一次性堆叠功能，而是让三类用户都能在首页第一屏快速进入自己的核心任务：

- 学习者：继续学习、案例训练、能力成长
- 工作者：新建案件、快速计算、资料管理
- 咨询者：快速自测、预约咨询、查看流程

## 2. 总体设计原则

### 2.1 统一与差异化

三端统一：

- 统一品牌视觉、导航位置、按钮样式、卡片结构、表单规范
- 统一账号系统、消息中心、历史记录、搜索入口
- 统一结果页结构：主结论、依据说明、风险提示、下一步建议

三端差异化：

- `learner` 强调学习路径、进度和反馈
- `expert` 强调效率、准确性和可追溯
- `client` 强调易懂、安心和低门槛

### 2.2 首页第一屏规则

每个角色首页第一屏只放 3 个最重要动作，避免信息过载：

- 学习者：首页放 `继续学习`、`案例练习`、`本周计划`
- 工作者：首页放 `新建案件`、`最近案件`、`专业工具`
- 咨询者：首页放 `快速自测`、`预约咨询`、`服务流程`

### 2.3 统一状态设计

所有页面都必须覆盖以下状态：

- 加载中：说明当前正在处理什么，而不是只显示转圈
- 空状态：说明为什么为空，并提供下一步动作
- 错误状态：说明错误原因、可执行建议、重试入口
- 草稿状态：未完成内容可恢复
- 只读状态：敏感内容或已归档内容不允许误编辑

## 3. 顶层导航与布局

### 3.1 导航建议

保留现有三端独立布局，但统一布局结构：

- 顶部：品牌、主导航、全局搜索、消息、个人中心
- 左侧可选二级导航：在内容多的页面中出现
- 主内容区：以卡片和分区方式承载任务
- 右侧辅助区：提醒、最近记录、帮助说明，仅桌面端展示

### 3.2 移动端规则

移动端使用底部导航，最多保留 4 个一级入口：

- 学习者：首页、学习、案例、我的
- 工作者：工作台、案件、工具、我的
- 咨询者：首页、自测、咨询、我的

复杂报表、批量导入、多列表对比仅保留桌面端完整体验，移动端只提供查看与简化编辑。

## 4. 学习者端原型

对应页面：

- `src/views/learner/DashboardPage.vue`
- `src/views/learner/ToolsPage.vue`
- `src/views/learner/KnowledgePage.vue`
- `src/views/learner/CasesPage.vue`
- `src/views/learner/CommunityPage.vue`

### 4.1 学习者工作台 `DashboardPage`

页面目标：让用户知道今天学什么、学到哪里、下一步做什么。

建议模块：

- 欢迎区
  - 显示用户身份、当前阶段、今日建议
  - 文案示例：`今日建议：完成 1 个章节、1 个案例、1 次工具训练`
- 学习路径卡
  - 以阶段式路径展示 `基础理论 -> 损伤鉴定 -> 病理判读 -> 案例推理 -> 工具实操`
  - 当前阶段高亮，下一阶段灰显
- 本周计划
  - 展示周目标、已完成数量、剩余任务
  - 支持一键切换 `轻量 / 标准 / 冲刺` 计划
- 能力进度
  - 不只显示单一进度条，改为 4 张能力卡
  - 维度建议：`理论掌握`、`案例分析`、`工具使用`、`知识回顾`
- 最近继续学习
  - 最近浏览课程、上次做到哪、继续按钮
- 错题与薄弱项
  - 显示最近 5 条错题和薄弱知识点

实现措施：

- 现有统计卡可以保留，但调整成有意义的学习指标
- 现有 `progressList` 改造成阶段进度和能力维度两组数据
- 首页第一屏不要出现社区内容，社区放第二屏之后

### 4.2 工具练习页 `ToolsPage`

页面目标：让学习者把计算器当作学习工具，而不只是结果工具。

建议模块：

- 工具分类区
  - 预测类工具
  - 计算估算工具
- 每个工具卡补充以下信息
  - 学习目标
  - 输入要求
  - 难度等级
  - 预计耗时
  - 是否有练习题
- 顶部筛选
  - 按主题、难度、是否已学习、是否已完成筛选
- 工具练习结果区
  - 不只展示结果，还要展示计算过程和依据说明
  - 提供 `再练一题` 和 `查看教学解析`

实现措施：

- 同一工具应区分 `学习模式` 与 `快速计算模式`
- 学习模式加入字段解释、错误提醒、参考区间说明
- 每个工具结果页增加 `适用场景` 与 `不适用场景`

### 4.3 知识库页 `KnowledgePage`

页面目标：让知识内容可学、可查、可串联。

建议模块：

- 顶部搜索
  - 支持搜术语、法规、案例、疾病、损伤类型
- 分类切换
  - `法规标准`、`教材资料`、`专题文章`、`教学视频`
- 推荐路径
  - 为新手提供 `从哪里开始学`
- 文章卡片
  - 显示难度、时长、前置知识、收藏、阅读进度
- 文中辅助功能
  - 术语解释
  - 图文标注
  - 段落收藏
  - 学后练习入口

实现措施：

- 当前资源卡补上 `难度`、`前置知识`、`学习状态`
- 阅读页底部固定显示 `相关案例` 与 `对应练习`

### 4.4 案例页 `CasesPage`

页面目标：训练应用能力，而不是只看答案。

建议模块：

- 案例分类
  - 按损伤类型、难度、是否典型、是否开放题筛选
- 案例流程
  - 案情摘要
  - 证据材料
  - 自主判断
  - 标准解析
  - 延伸知识
- 评分维度
  - 信息提取
  - 依据引用
  - 结论合理性

实现措施：

- 每个案例至少提供 `自己先答` 的区域
- 不要一打开就显示标准答案

### 4.5 社区页 `CommunityPage`

页面目标：辅助学习，不喧宾夺主。

建议模块：

- 热门问答
- 学习打卡
- 同阶段同学讨论
- 优质资料分享

实现措施：

- 社区默认按学习主题分区，而不是按时间流刷帖
- 增加 `我也遇到这个问题` 按钮，便于聚合同类问题

### 4.6 学习者评估机制

建议采用双轨评估：

- 知识掌握：选择题、判断题、知识点测验
- 应用能力：案例分析、工具操作、结论推理

评分建议：

- 知识掌握 40%
- 案例分析 40%
- 工具实操 20%

必须具备：

- 即时反馈
- 错题回顾
- 阶段测验
- 学习报告

## 5. 工作者端原型

对应页面：

- `src/views/expert/DashboardPage.vue`
- `src/views/expert/ToolsPage.vue`
- `src/views/expert/LibraryPage.vue`
- `src/views/expert/QAPage.vue`
- `src/views/expert/NursingPage.vue`

建议后续新增页面：

- `src/views/expert/CasesPage.vue`
- `src/views/expert/CaseDetailPage.vue`

### 5.1 工作者工作台 `DashboardPage`

页面目标：让工作者进入系统后立即处理案件和任务。

建议模块：

- 核心操作条
  - `新建案件`
  - `打开最近案件`
  - `进入专业工具`
- 今日待办
  - 待补资料
  - 待复核结论
  - 待回复咨询
- 案件看板
  - `待处理`、`处理中`、`待复核`、`已归档`
- 最近使用工具
  - 按使用频率排序
- 风险提醒
  - 缺少关键字段
  - 异常数值未确认
  - 结论未复核

实现措施：

- 当前 KPI 卡片可以保留，但优先展示任务型数据而不是静态数字
- 当前待办区改造成带优先级标签和截止时间的任务列表

### 5.2 专业工具页 `ToolsPage`

页面目标：支持准确、可追溯、可批量的专业运算与辅助判断。

建议模块：

- 顶部工具搜索
- 工具分组
  - 高频工具
  - 预测分析
  - 法医估算
  - 赔偿相关
- 工具卡信息
  - 适用场景
  - 输入项数量
  - 最近更新时间
  - 依据标准
  - 是否支持批量
- 最近使用
- 收藏工具

结果页统一规范：

- 主结论卡
- 计算过程明细
- 参数表
- 引用标准
- 风险提示
- 导出按钮

实现措施：

- 学习者和工作者虽然可以共用算法，但界面层必须分开
- 工作者端默认展示更完整字段、批量入口、导出入口
- 对异常值增加人工确认步骤

### 5.3 资料库页 `LibraryPage`

页面目标：让工作者快速找到权威标准、模板和参考资料。

建议模块：

- 分类导航
  - 标准规范
  - 文书模板
  - 鉴定依据
  - 历史案例
  - 常见争议问题
- 高级筛选
  - 类型、年份、地区、状态、适用案件
- 收藏夹
- 最近查看

实现措施：

- 每份资料显示 `适用场景` 和 `更新日期`
- 文书模板支持 `一键套用到当前案件`

### 5.4 在线答疑页 `QAPage`

页面目标：沉淀专业知识与协作经验。

建议模块：

- 待回答问题
- 已解决问题
- 按专题浏览
- 高质量回答推荐

实现措施：

- 问题发布时要求选择专题和案件类型
- 回答可标记为 `标准答案`、`经验建议`、`待核实`

### 5.5 护理相关页 `NursingPage`

页面目标：提供专业评估工具与结构化输出。

建议模块：

- 护理等级相关计算
- 误工/营养/依赖程度评估
- 条件说明
- 文书建议语句

实现措施：

- 结果页不只给数值，必须提供报告引用段落
- 对不同地区标准保留切换入口

### 5.6 工作者案件管理建议

建议新增完整案件中心，原因是工具和资料最终都应服务于案件流程。

案件中心应支持：

- 一键新建案件模板
- 表单式快速录入
- 向导式复杂案件录入
- 上传材料
- 绑定计算结果
- 自动生成报告草稿
- 权限分级与审计日志

案件主筛选优先级：

- 先按状态
- 再按案件类型
- 最后按时间和负责人

## 6. 咨询者端原型

对应页面：

- `src/views/client/DashboardPage.vue`
- `src/views/client/CheckPage.vue`
- `src/views/client/ConsultPage.vue`
- `src/views/client/KnowledgePage.vue`

建议后续新增页面：

- `src/views/client/ProgressPage.vue`

### 6.1 咨询者首页 `DashboardPage`

页面目标：让用户快速知道自己该从哪里开始。

建议模块：

- Hero 区
  - 明确告诉用户可提供什么服务
  - 放置 `快速自测` 主按钮
- 三步流程
  - 自测
  - 咨询
  - 后续处理
- 常见问题
  - 收费
  - 所需材料
  - 响应时间
- 安心说明
  - 仅供参考
  - 隐私保护
  - 专家资质

实现措施：

- 首页语言全部使用通俗表达
- 不要把复杂百科和专业解释放到第一屏

### 6.2 初步检测页 `CheckPage`

页面目标：帮助用户完成结构化自测。

建议流程：

- 第 1 步：选择问题类型
- 第 2 步：填写症状或伤情信息
- 第 3 步：上传辅助材料
- 第 4 步：查看初步结果
- 第 5 步：选择是否咨询

结果页建议模块：

- 初步风险等级
- 结果解释
- 为什么得到这个结果
- 需要补充什么材料
- 下一步建议

实现措施：

- 采用分步式表单，不建议一屏填完
- 每步只保留核心字段
- 自动保存草稿

### 6.3 咨询服务页 `ConsultPage`

页面目标：完成预约、提问、跟踪服务。

建议改造方向：

- `预约咨询`
  - 先选问题类型，再推荐专家
  - 展示专家领域、可预约时段、价格区间、服务方式
- `在线问答`
  - 用于简单问题
  - 复杂问题自动引导预约
- `进度查询`
  - 展示已提交咨询的当前状态

实现措施：

- 当前双 tab 结构可以保留
- 专家卡片增加响应时间、评价、擅长方向
- 提问前先做结构化问题引导，减少无效提问

### 6.4 知识页 `KnowledgePage`

页面目标：普及常识，降低焦虑，促进转化。

建议分类：

- 常见问题
- 流程说明
- 风险预防
- 术语解释

内容要求：

- 标题必须口语化
- 正文先给结论，再解释原因
- 每篇文章底部提供 `我需要进一步咨询` 的入口

### 6.5 服务进度追踪

建议新增进度页或在咨询页内嵌时间轴。

状态建议：

- 已提交
- 审核中
- 待补资料
- 已预约
- 已完成

提醒方式：

- 站内消息
- 短信或微信提醒
- 到期前提醒补资料

## 7. 计算器与专业算法统一规范

本部分适用于学习者端工具、工作者端专业工具、咨询者端自测结果。

### 7.1 算法来源管理

每个算法建立元数据档案，至少包含：

- 算法名称
- 适用场景
- 不适用场景
- 公式或规则来源
- 参考标准名称
- 版本号
- 审核人
- 更新时间

### 7.2 输入验证规则

每类工具都要配置：

- 字段类型
- 是否必填
- 允许范围
- 单位
- 默认单位
- 是否支持换算
- 异常值处理策略

异常值策略建议：

- 超出合理区间时先警告
- 超出专业上限时禁止继续
- 缺少关键字段时不输出最终结论

### 7.3 个体差异处理

如果结果受个体因素影响，应明确纳入：

- 年龄
- 性别
- 身高体重
- 部位
- 时间因素
- 病史或特殊体质

展示策略：

- 优先展示结果区间
- 补充置信提示
- 说明哪些因素会影响结果

### 7.4 结果页统一模板

所有结果页统一为六段：

1. 主结论
2. 参考区间或等级
3. 计算依据
4. 风险提示
5. 下一步建议
6. 导出与留档

三端差异化表达：

- 学习者：强调教学解释
- 工作者：强调过程、证据和导出
- 咨询者：强调通俗解释和后续动作

## 8. 交互细节规范

### 8.1 反馈设计

- 保存成功：明确提示已保存到哪里
- 导出成功：提示文件格式和内容范围
- 提交成功：显示下一步和预计等待时间
- 删除或覆盖前：二次确认

### 8.2 帮助信息

帮助要分层：

- 字段级帮助：悬浮提示
- 模块级帮助：说明卡片
- 页面级帮助：新手引导

### 8.3 快捷操作

优先提供给工作者：

- `/` 聚焦搜索
- `N` 新建案件
- `Ctrl + S` 保存草稿
- `Ctrl + P` 导出报告

移动端不强调快捷键，强调大按钮、清晰步骤和少输入。

   - 增加难度、前置知识、学习状态和相关推荐

## 11. 结论

这套产品不适合做成一套统一内容、仅换文案的三端页面，而应该基于同一设计系统，做三种完全不同的任务型首页和结果型页面。

最关键的设计动作有三个：

- 学习者端建立“成长闭环”
- 工作者端建立“案件闭环”
- 咨询者端建立“服务闭环”

只要这三个闭环建立起来，后续无论增加算法、案例库、文书导出还是机构协作，整体结构都会比较稳。
